О методологии Ярослава
В основе подхода — пять плоскостей Джесси Гарретта, адаптированных под 2025–2026 год. Любой продукт строится слоями снизу вверх:
·   	Стратегия — зачем это нужно и кому
·   	Скоп — что войдёт в первую версию
·   	Структура — как элементы связаны между собой
·   	Скелет — как всё разложено на экране
·   	Поверхность — что видит пользователь
К этим пяти добавляется шестой слой — AI-native исполнение: дизайн и код создаются с помощью искусственного интеллекта, а не вопреки ему.
Продакт-менеджер, понимающий эти плоскости, разговаривает с дизайнером и разработчиком на одном языке — и принимает решения, опираясь на систему, а не на интуицию.
1. Композиция в интерфейсах
Композиция — это то, куда смотрит пользователь в первые три секунды. Три правила, которые работают в любом UI:
·   	Визуальная иерархия: самое важное — крупнее, темнее, с большим отступом
·   	Z- и F-паттерны: глаз движется по предсказуемому маршруту — ключевая информация должна быть на его пути
·   	Белое пространство: пустота — не ошибка, а инструмент. Элемент с воздухом вокруг становится важным
Для PM: если экран кажется «перегружен» — это нарушенная иерархия. Попросите дизайнера показать, какой элемент главный.
2. Типографика в интерфейсах
Шрифт — не декорация, а носитель смысла. Для продуктового дизайна достаточно трёх уровней:
·   	Заголовок (H1–H2): ориентация, куда пользователь попал
·   	Тело (Body): основной контент — читаемость важнее красоты
·   	Вспомогательный (Caption, Label): метки, подсказки, статусы
Для PM: если текст нужно «догадаться прочитать» — это баг, не фича.
3. Цветовые схемы и контраст
Цвет в интерфейсе решает три задачи: бренд, иерархия, состояние. Минимальный словарь:
·   	Primary — цвет действия (кнопка, ссылка)
·   	Neutral — фон, текст, границы
·   	Semantic — зелёный (успех), красный (ошибка), жёлтый (предупреждение)
Контраст — не про красоту, а про доступность. Минимум по WCAG: 4.5:1 для обычного текста.
4. Компоненты UI: кнопки, поля, формы
Компоненты — строительные блоки интерфейса. Каждый имеет состояния:
·   	Кнопка: default → hover → active → disabled → loading
·   	Поле ввода: empty → focused → filled → error → success
·   	Форма: сообщения об ошибках должны объяснять проблему, а не просто сигнализировать о ней
Для PM: принимая решение «добавить кнопку», уточняйте — это новый компонент или вариант существующего? Неконтролируемый рост компонентов замедляет разработку.
5. Wireframe-макеты
Wireframe — скелет экрана без дизайна. Его задача — проверить логику, не вкладывая в неё эстетику. Три уровня:
·   	Lo-Fi (набросок): прямоугольники и текст, создаётся за 20 минут
·   	Mid-Fi (каркас): реальные пропорции и иерархия, без цвета
·   	Hi-Fi (прототип): финальный вид, полная интерактивность
PM-практика: Lo-Fi wireframe — лучший способ синхронизироваться с командой до того, как дизайнер потратит день на макет.
6. Интерактивные прототипы
Прототип позволяет «потрогать» продукт до его существования. В 2026 году Lo-Fi интерактивный прототип строится с помощью AI за 30–60 минут.
·   	Тест гипотез на пользователях без написания кода
·   	Синхронизация с разработчиками: «вот что нужно построить»
·   	Фиксация договорённостей команды
7. Адаптивный дизайн
Продукт должен работать на всех размерах экрана. Три стратегии:
·   	Mobile First: сначала дизайн для телефона, потом расширяем на десктоп
·   	Breakpoints: фиксированные точки перестройки сетки (320, 768, 1024, 1440px)
·   	Fluid Layout: элементы масштабируются относительно ширины экрана
Для PM: при оценке задачи «сделать адаптив» уточняйте, какие устройства в приоритете по данным аналитики.
8. Доступность (WCAG)
Доступность улучшает UX для всех, не только для людей с особенностями. Минимальный чеклист:
·   	Контраст текста не ниже 4.5:1
·   	Все интерактивные элементы доступны с клавиатуры
·   	Изображения имеют alt-текст
·   	Сообщения об ошибках — текстом, не только цветом
10. Микровзаимодействия и анимация
Микровзаимодействие — реакция интерфейса на действие пользователя: кнопка нажалась, форма отправилась, элемент перетащили. Принципы хорошей анимации:
·   	Длительность: 150–300ms — почти незаметно, но есть
·   	Easing: движение ускоряется или замедляется, а не линейное
·   	Цель: анимация объясняет, что произошло, не просто украшает
11. Микрокопирайт в интерфейсе
UX writing — тексты кнопок, ошибок, подсказок, онбординга. Три правила:
·   	Кнопка = действие: не «OK», а «Сохранить изменения»
·   	Ошибка = объяснение + путь решения: не «Ошибка», а «Неверный email — проверьте формат»
·   	Пустое состояние = приглашение: не «Нет данных», а «Добавьте первый проект»
12. Информационная архитектура
IA — карта продукта: как разделы связаны, как пользователь добирается от A до B. Инструменты:
·   	Карточная сортировка: пользователи раскладывают функции по группам — вы узнаёте их ментальную модель
·   	Customer Journey Map: путь от осознания проблемы до результата
·   	Screen Flow: все экраны и переходы на одном листе
Для PM: IA — ваша ответственность, не дизайнера. Если навигация непонятна, проблема в продуктовых решениях.
14. Передача в разработку (Handoff)
Handoff — момент, когда дизайн становится кодом. Частые проблемы:
·   	Разработчик не знает, как компонент ведёт себя в крайних состояниях
·   	Отступы и размеры указаны только для идеального случая
·   	Анимации не описаны
Лучший handoff в 2026: дизайнер создаёт AGENTS.md — файл инструкций для AI-агента (Cursor, Claude Code), который реализует компонент без ручного перевода.
