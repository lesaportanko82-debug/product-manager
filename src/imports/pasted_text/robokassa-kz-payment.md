Нужно реализовать в этом приложении полноценную оплату через Robokassa KZ с тестовым режимом, корректным возвратом пользователя, обработкой успешной и неуспешной оплаты, и безопасной серверной логикой.

ВАЖНО:
- Не ломай существующую архитектуру приложения.
- Не удаляй текущие экраны, стили, авторизацию и бизнес-логику.
- Вноси изменения аккуратно и последовательно.
- Сначала проанализируй текущую структуру проекта, маршруты, навигацию, auth flow, Supabase integration и существующие серверные функции.
- После анализа внедри оплату нативно в текущую архитектуру.
- Если каких-то файлов нет, создай их.
- Если каких-то маршрутов нет, добавь их.
- Не делай заглушку вместо рабочей интеграции.

ЦЕЛЬ:
Добавить рабочую оплату через Robokassa для покупки доступа к курсу/подписке/платному продукту.

ТЕКУЩИЕ ДАННЫЕ:
- Merchant login: ROBOKASSA_LOGIN
- Боевой пароль 1: ROBOKASSA_PASSWORD1
- Боевой пароль 2: ROBOKASSA_PASSWORD2
- Используется SHA-256
- В Robokassa уже настроены:
  - Result URL = https://www.product-intensive.com/api/payment/result
  - Success URL = https://www.product-intensive.com/payment-success
  - Fail URL = https://www.product-intensive.com/payment-fail
  - Result URL method = POST
  - Success URL method = GET
  - Fail URL method = GET
- Для тестового режима в Robokassa уже настроены отдельные тестовые пароли:
  - ROBOKASSA_TEST_PASSWORD1
  - ROBOKASSA_TEST_PASSWORD2
- Для тестовых платежей запрос должен отправляться с IsTest=1
- Для тестового режима использовать именно тестовые пароли, а не боевые

ЧТО НУЖНО СДЕЛАТЬ:

1. Найти или создать централизованную payment-логику
Реализуй безопасную серверную генерацию ссылки на оплату.
Нельзя подписывать платеж на клиенте.
Подпись должна собираться только на сервере.

2. Создать серверный endpoint для старта оплаты
Создай endpoint:
POST /api/payment/create

Он должен:
- принимать данные о покупке:
  - productId / planId / price / currency / userId / email
- валидировать входные параметры
- генерировать уникальный invoice id
- сохранять pending payment в базе
- собирать ссылку оплаты Robokassa
- подписывать запрос через SHA-256
- возвращать frontend готовый payment URL для редиректа

3. Формирование ссылки на оплату
При создании payment URL передавай:
- MerchantLogin
- OutSum
- InvId
- Description
- SignatureValue
- ResultUrl2 / SuccessUrl2 / FailUrl2 только если это поддерживается текущей архитектурой
- IsTest=1 для тестового режима
- при необходимости кастомные параметры Shp_, если они уже используются в проекте

Подпись формируй корректно для SHA-256.
Используй:
- тестовые пароли в тестовом режиме
- боевые пароли в боевом режиме

4. Создать серверный endpoint для callback от Robokassa
Создай endpoint:
POST /api/payment/result

Он должен:
- принимать callback от Robokassa
- читать OutSum, InvId, SignatureValue и другие нужные параметры
- пересчитывать подпись через SHA-256 с использованием Password #2
- в тестовом режиме использовать тестовый пароль #2
- сравнивать подпись безопасно и без ошибок регистра
- если подпись невалидна, возвращать ошибку
- если валидна:
  - найти payment по invoice id
  - отметить payment как paid
  - записать raw callback payload в лог
  - активировать купленный доступ пользователю
  - обновить subscription / access level / purchase status в базе
- вернуть строго:
  OK{InvId}
  без лишнего текста

5. Создать frontend flow оплаты
Найди кнопку покупки / оплаты в приложении.
Если её нет — добавь на логичное место.
При нажатии:
- вызвать POST /api/payment/create
- получить payment URL
- сделать redirect пользователя на Robokassa

Обязательно:
- показать loading state
- обработать network error
- не допускать повторного запуска платежа много раз подряд
- отображать понятную ошибку пользователю

6. Создать success page
Создай route/page:
 /payment-success

Эта страница должна:
- существовать как полноценный маршрут, чтобы приложение не падало
- показывать пользователю понятное сообщение об успешной оплате
- пробовать подтянуть payment status из backend
- если callback уже обработан — показать подтверждение доступа
