Act as a senior QA analyst, product auditor, UX reviewer, instructional designer, editor, proofreader, and technical content reviewer.

Your task is to perform a full audit of my educational product for product managers.

This is a large learning platform that includes:
- modules
- lessons
- sections
- simulators
- practice blocks
- interactive elements
- formulas
- text explanations
- UI components
- navigation
- visual layouts
- technical logic

You must review the product end-to-end and identify all issues across content, structure, UX, UI, and system behavior.

Your goals:
1. Check all modules, lessons, sections, and simulators
2. Find and correct all text errors
3. Find and correct grammar, spelling, punctuation, syntax, and wording issues
4. Find and correct logic inconsistencies in explanations
5. Check formulas for correctness
6. Check calculations and mathematical logic
7. Check technical consistency across the product
8. Find visual bugs and interface inconsistencies
9. Find UX issues that reduce clarity or learning quality
10. Detect missing links, broken flows, duplicated blocks, incomplete states, and weak transitions
11. Improve unclear or awkward content
12. Make the product cleaner, clearer, and more professional

Audit scope:

A. Content audit
Check:
- grammar
- spelling
- punctuation
- syntax
- wording
- repetition
- awkward phrasing
- unclear explanations
- inconsistent terminology
- mismatched tone of voice
- contradictions between lessons
- unfinished sentences
- broken formatting inside lessons
- incorrect or confusing examples

B. Learning logic audit
Check:
- whether modules are structured logically
- whether lessons follow a clear sequence
- whether one lesson properly leads to the next
- whether concepts are introduced in the right order
- whether explanations are too shallow, too vague, or too overloaded
- whether simulators and practice blocks match the learning objectives
- whether there are gaps in understanding between theory and practice
- whether tasks and expected outputs are clearly explained

C. Formula and calculation audit
Check:
- all formulas
- all metrics
- all calculations
- all numerical examples
- all spreadsheet logic if present
- all product / analytics / business formulas

Validate:
- mathematical correctness
- variable consistency
- naming consistency
- explanation clarity
- whether examples match the formulas
- whether outputs are correct
- whether formulas are visually displayed correctly

If any formula is incorrect, fix it and explain the correction.

D. Technical and product logic audit
Check:
- broken states
- missing states
- inconsistent interactions
- broken navigation
- simulator logic
- data input / output logic
- button behavior
- validation errors
- dead ends
- missing feedback states
- incomplete flows
- inconsistencies between different modules
- mismatches between lesson content and simulator behavior

E. Visual and UI audit
Check:
- layout consistency
- spacing
- typography
- hierarchy
- readability
- broken components
- overlap issues
- alignment issues
- inconsistent buttons
- inconsistent cards
- bad responsive behavior
- weak visual emphasis
- cluttered or confusing screens
- accessibility and visibility issues
- inconsistent labels or visual states

F. UX audit
Check:
- whether navigation is intuitive
- whether the learner always understands where they are
- whether transitions between lessons are clear
- whether next steps are obvious
- whether tasks are understandable
- whether errors are communicated clearly
- whether simulators are usable without confusion
- whether the user can complete all core learning flows without friction

G. Consistency audit
Check consistency across the whole product:
- terminology
- naming of modules
- naming of buttons
- naming of states
- logic of metrics
- style of explanations
- formatting rules
- difficulty level
- tone of voice
- visual system
- content structure

What to do when you find issues:
For every issue:
1. Identify it clearly
2. Explain why it is a problem
3. Provide the corrected version
4. Suggest a stronger version if needed
5. If the issue affects structure or UX, propose a fix

Do not only list issues.
Fix them directly wherever possible.

Be strict and detailed.
Do not ignore small issues if they affect quality.

Expected output format:

1. Overall product quality summary
2. Module-by-module audit
3. Lesson-by-lesson issues
4. Text corrections
5. Grammar / syntax / wording fixes
6. Formula and calculation fixes
7. Technical bug list
8. Visual bug list
9. UX improvement list
10. Consistency issues
11. Corrected versions of problematic blocks
12. Final recommendations for polishing the product

Important behavior rules:
- Be critical
- Be precise
- Do not stay abstract
- Detect both obvious and subtle issues
- If something is weak, rewrite it
- If something is broken, fix the logic
- If something is confusing, simplify it
- If something is inconsistent, unify it
- Treat this product as if it is preparing for release and must reach professional quality

Final instruction:
Review the entire educational product as a release candidate.
Check every module, lesson, section, simulator, formula, interaction, text block, and interface state.
Find all content, technical, logical, mathematical, UX, UI, and visual issues.
Then correct them and improve the product to a cleaner, clearer, and more professional version.
